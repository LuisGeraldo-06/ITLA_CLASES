05. Formularios

Los formularios permiten recoger información de quien visita una página: iniciar sesión, comprar, reservar, opinar o buscar. Todos los ejemplos usan el aspecto por defecto del navegador, sin CSS propio, para ver cómo se comporta cada control de forma nativa.

Anatomía de un formulario

Un formulario es un contenedor <form> con controles dentro. Cada control lleva un name (el nombre del dato) y una <label> que explica qué se pide. Al pulsar el botón de envío, el navegador junta todos los pares name=valor y los manda a la dirección indicada en action.

Elemento / atributoPara qué sirveEjemplo
<form>agrupa los controles que se envían juntos<form action="#" method="get">
actiondirección a la que se envían los datosaction="/buscar"
methodget (datos en la URL) o post (datos ocultos en la petición)method="post"
<label>texto asociado a un control mediante for e id<label for="correo">
<input>control de una línea; su type cambia el comportamiento<input type="email">
<textarea>texto de varias líneas<textarea rows="4">
<select> y <option>lista desplegable de opciones<option value="cr">
<fieldset> y <legend>agrupan controles relacionados con un título<legend>Envío</legend>
<button>envía (submit), limpia (reset) o no hace nada (button)<button type="submit">
name y valuenombre del dato y valor que se envíaname="talla" value="m"
required, min, max, patternvalidación nativa del navegador, sin JavaScriptminlength="8"
autocompleteayuda al navegador a rellenar datos guardadosautocomplete="email"

Ejemplo 12

Campos disabled y readonly

En una factura electrónica algunos datos no se pueden cambiar. Parecen iguales, pero se comportan distinto: readonly se puede seleccionar y sí se envía; disabled no recibe el foco y no se envía. Un fieldset disabled desactiva todo su contenido de una vez.

Ejemplo 15

Cómo viajan los datos: GET, POST y name

El mismo filtro de una tienda en línea enviado de dos maneras. Con get, mira la barra de direcciones después de enviar: verás ?categoria=...&precio_max=.... Con post, la URL no cambia porque los datos viajan dentro de la petición. El campo sin name nunca se envía.

Ejemplo 18

Desactivar la validación con novalidate

Dos copias del mismo formulario de suscripción. La primera valida normalmente. La segunda tiene novalidate en el <form>: se envía aunque el correo esté vacío o mal escrito. Se usa cuando JavaScript se encargará de validar con mensajes propios; el servidor siempre debe volver a validar.
