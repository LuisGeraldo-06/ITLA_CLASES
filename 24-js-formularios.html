Formularios: leer, validar y reaccionar

HTML ya sabe validar (required, type="email", min, pattern…) y CSS ya sabe pintar los estados. JavaScript agrega lo que falta: leer lo que la persona escribió, reaccionar mientras escribe, mostrar mensajes propios y decidir qué pasa al enviar sin recargar la página.

Leer y escribir valoresQué devuelve
campo.valueel texto del campo. Siempre es string, incluso en type="number"
campo.valueAsNumberel valor como número (en number, range y fechas). Vacío → NaN
campo.checkedtrue / false en checkbox y radio
campo.filesla lista de archivos de un input type="file"
select.value / select.selectedIndexel value de la opción elegida / su posición
form.elements.nombreel campo cuyo name es "nombre"
new FormData(form)todos los campos con name, listos para recorrer o enviar
datos.get("x") / datos.getAll("x")un valor / todos los valores con ese name (checkbox múltiples)
Object.fromEntries(datos)un objeto { nombre: "…", correo: "…" }
form.reset()vuelve todos los campos a su valor inicial
EventoCuándo ocurre
inputcon cada tecla, cada movimiento del range, cada clic en un checkbox
changecuando el valor queda confirmado (al salir del campo, al elegir en un select o un archivo)
submital enviar el formulario (botón submit o Enter). Solo si pasa la validación HTML
resetal pulsar un button type="reset" o llamar a form.reset()
invaliden cada campo que no pasa la validación al intentar enviar
paste / keydownal pegar / al pulsar una tecla (antes de que se escriba)
dragover / dropmientras se arrastra algo encima / al soltarlo
Constraint Validation APIPara qué sirve
form.checkValidity()true si todos los campos cumplen sus reglas (no muestra nada)
campo.reportValidity()igual, pero además muestra el globito de error del navegador

campo.validationMessageel texto de error que mostraría el navegador
campo.setCustomValidity("texto")marca el campo como inválido con tu mensaje. Con "" vuelve a ser válido

Leer valores: .value, .checked y .valueAsNumber

Cambia lo que quieras en el perfil y pulsa Ejecutar. Fíjate en que .value de un campo numérico es texto, y .valueAsNumber ya es número. Si borras la edad, valueAsNumber da NaN.

Plan

Para los radio no se lee cada botón: se busca el marcado del grupo con el selector input[name='plan']:checked. Un checkbox se lee con .checked, no con .value (su value es siempre el mismo).

Ejemplo 2

Enviar sin recargar: submit, FormData y Object.fromEntries

Un formulario de contacto. Al enviarlo, preventDefault() evita que la página se recargue; FormData junta todos los campos que tienen name y Object.fromEntries los convierte en un objeto normal.

Aún no se envió nada.

El evento submit se escucha en el formulario, no en el botón: así también funciona al pulsar Enter. Como los campos son required, el navegador no deja enviar (y no se dispara submit) mientras falte algo.

Reglas propias: setCustomValidity() y reportValidity()

HTML no sabe si un nombre de usuario ya está ocupado. Con setCustomValidity marcamos el campo como inválido con nuestro propio mensaje, y reportValidity lo muestra en el globito del navegador. Prueba con «admin», «ana» o «soporte».

«admin», «ana» y «soporte» ya están ocupados.

Mientras el mensaje propio no sea "", el campo cuenta como inválido: el navegador bloquea el envío y aplica :invalid en CSS. Por eso hay que limpiarlo con setCustomValidity("") cuando el valor vuelve a estar bien.

Validación en vivo con errores accesibles

El estilo de los sitios reales: el mensaje aparece debajo de cada campo mientras escribes (evento input) y al enviar se revisan todos. aria-invalid marca el error y aria-describedby une el campo con su mensaje para los lectores de pantalla.

El evento input se escucha una sola vez en el formulario y event.target dice qué campo cambió (delegación, como en la lección de eventos). Al fallar, el foco va al primer campo con error.

    <script>
        const encuesta = document.querySelector("#encuesta");
        const pasos = [...encuesta.querySelectorAll(".paso")];
        const encuestaProgreso = document.querySelector("#encuesta-progreso");
        const encuestaAtras = document.querySelector("#encuesta-atras");
        const encuestaSiguiente = document.querySelector("#encuesta-siguiente");
        const encuestaEnviar = document.querySelector("#encuesta-enviar");
        const encuestaResumen = document.querySelector("#encuesta-resumen");
        let pasoActual = 0;

        const mostrarPaso = (numero) => {
            pasoActual = numero;
            pasos.forEach((paso, i) => {
                paso.hidden = i !== numero;
            });
            const esUltimo = numero === pasos.length - 1;
            encuestaAtras.hidden = numero === 0;
            encuestaSiguiente.hidden = esUltimo;
            encuestaEnviar.hidden = !esUltimo;
            encuestaProgreso.textContent = `Paso ${numero + 1} de ${pasos.length}`;
        };

        const pasoValido = () => {
            const campos = [...pasos[pasoActual].querySelectorAll("input, select, textarea")];
            return campos.every((campo) => campo.reportValidity());
        };

        encuestaSiguiente.addEventListener("click", () => {
            if (pasoValido()) {
                mostrarPaso(pasoActual + 1);
            }
        });

        encuestaAtras.addEventListener("click", () => {
            mostrarPaso(pasoActual - 1);
        });

        encuesta.addEventListener("submit", (event) => {
            event.preventDefault();
            if (!pasoValido()) {
                return;
            }
            const datos = new FormData(encuesta);
            const filas = encuestaResumen.querySelector("tbody");
            filas.innerHTML = "";
            for (const campo of Object.keys(Object.fromEntries(datos))) {
                const fila = filas.insertRow();
                fila.insertCell().textContent = campo;
                fila.insertCell().textContent = datos.getAll(campo).join(", ");
            }
            encuestaResumen.hidden = false;
            encuesta.reset();
            mostrarPaso(0);
        });
    </script>
