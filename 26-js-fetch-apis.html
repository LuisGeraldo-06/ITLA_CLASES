Cómo habla una página con un servidor

Una API (interfaz de programación) es una dirección web pensada para programas, no para personas: en vez de devolver una página HTML devuelve datos, casi siempre en formato JSON. JSON es texto que se parece a un objeto de JavaScript, pero con reglas más estrictas: las claves van entre comillas dobles y no hay funciones ni comentarios.

La conversación siempre es igual: el navegador envía una petición (método + URL + a veces un cuerpo) y el servidor contesta con una respuesta (un código de estado + cabeceras + un cuerpo).

CORS: por seguridad, el navegador solo deja leer respuestas de otro dominio si ese servidor lo permite. Todas las APIs de esta lección lo permiten; si algún día ves “blocked by CORS policy” en la consola, el problema está en el servidor, no en tu código.

Ejemplo 1

Tu primer fetch

Pedimos un usuario de prueba a JSONPlaceholder. fetch devuelve la respuesta; .json() lee el cuerpo y lo convierte en objeto. Las dos cosas toman tiempo, por eso van con await.

Ejemplo 2

JSON: texto con forma de objeto

Los servidores no envían objetos, envían texto. JSON.stringify convierte un objeto en ese texto y JSON.parse hace el camino de vuelta. Si el texto no es JSON válido, parse lanza un error.

Ejemplo 3

Promesas: then/catch frente a async/await

fetch devuelve una promesa: un valor que llegará más tarde. Se puede encadenar con .then() o esperar con await. Hacen lo mismo; await se lee de arriba hacia abajo y se combina con try/catch.

Ejemplo 4

response.ok y los errores HTTP

Pedir la publicación 9999, que no existe, no hace fallar a fetch: llega una respuesta con estado 404. Por eso conviene una función que revise respuesta.ok y lance un error si algo salió mal.

Ejemplo 5

setTimeout, setInterval y una promesa «esperar»

setTimeout ejecuta algo una vez después de un tiempo; setInterval lo repite hasta llamar a clearInterval. Envolviendo setTimeout en una promesa obtenemos esperar(ms), muy útil con await.
